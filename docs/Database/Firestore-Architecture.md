# Ascend AI: Firestore Database Architecture

This document serves as the single source of truth for the Ascend AI Firestore Database. 

## Overview & Architecture Decision
The database employs a **User-Centric Subcollection Architecture**. Since Ascend AI revolves around a single user's transformation journey, all data generated by or relevant to a specific user is stored under their root document (`users/{userId}`).

**Design Rationale:**
- **Isolation & Security:** User data is inherently siloed. A single security rule `match /users/{userId}/{document=**}` can securely lock down all subcollections.
- **Scalability:** By avoiding massive unbounded root collections for high-frequency logs (like `daily_logs` or `activities`), we reduce indexing overhead and avoid hotspots.
- **Read Optimization:** Fetching a user's dashboard only requires querying their specific subcollections, making queries fast and cheap.
- **Offline Persistence:** Firestore caches data locally. A user-scoped hierarchy ensures the device only caches and syncs data belonging to the logged-in user.

## 1. Collection Hierarchy

```text
users/ (Root Collection)
 └── {userId} (Document)
      ├── settings/
      ├── chapters/
      ├── daily_logs/
      ├── activities/
      ├── nutrition_logs/
      ├── water_logs/
      ├── journal_entries/
      ├── progress_photos/
      ├── achievements/
      ├── streaks/
      ├── notifications/
      └── ai_conversations/
            └── {conversationId}
                  └── messages/
```

## 2. Document Structures

### `users` (Root Collection)
Contains long-lived user profile information and aggregated stats.
- **Path:** `users/{userId}`
- **Fields:**
  - `id` (string): The user's UID.
  - `email` (string)
  - `displayName` (string | null)
  - `photoURL` (string | null)
  - `profile` (map): `age`, `height`, `weight`, `gender`, etc.
  - `goals` (map): High-level targets (e.g., target weight).
  - `currentChapterId` (string | null): Reference to active chapter.
  - `currentStats` (map): Cached rollups (e.g., total workouts).
  - `createdAt` (timestamp)
  - `updatedAt` (timestamp)

### `settings` (Subcollection)
User preferences. We use a single document `default` for simplicity.
- **Path:** `users/{userId}/settings/default`
- **Fields:**
  - `theme` (string): 'light', 'dark', 'system'
  - `notifications` (map): boolean flags for different types.
  - `aiPreferences` (map): tone, verbosity.
  - `updatedAt` (timestamp)

### `chapters` (Subcollection)
Represents phases of the user's journey.
- **Path:** `users/{userId}/chapters/{chapterId}`
- **Fields:**
  - `title` (string)
  - `description` (string)
  - `status` (string): 'not-started', 'in-progress', 'completed'
  - `startDate` (timestamp | null)
  - `endDate` (timestamp | null)
  - `tasksCompleted` (number)
  - `totalTasks` (number)
  - `createdAt` (timestamp)

### `daily_logs` (Subcollection)
Aggregated daily metrics. Typically one document per day.
- **Path:** `users/{userId}/daily_logs/{dateString}` (e.g. `2026-07-27`)
- **Fields:**
  - `date` (string): ISO date string.
  - `mood` (number): 1-5 scale.
  - `energy` (number): 1-5 scale.
  - `sleepHours` (number)
  - `notes` (string)
  - `createdAt` (timestamp)
  - `updatedAt` (timestamp)

### `activities` (Subcollection)
Specific tracked workouts or events.
- **Path:** `users/{userId}/activities/{activityId}`
- **Fields:**
  - `type` (string): 'running', 'lifting', 'meditation'
  - `durationMinutes` (number)
  - `caloriesBurned` (number | null)
  - `metrics` (map): e.g., distance, sets, reps.
  - `date` (timestamp)
  - `createdAt` (timestamp)

### `nutrition_logs` (Subcollection)
Meals and macros tracked.
- **Path:** `users/{userId}/nutrition_logs/{logId}`
- **Fields:**
  - `mealType` (string): 'breakfast', 'lunch', 'dinner', 'snack'
  - `calories` (number)
  - `protein` (number)
  - `carbs` (number)
  - `fat` (number)
  - `date` (timestamp)
  - `createdAt` (timestamp)

### `water_logs` (Subcollection)
Hydration tracking.
- **Path:** `users/{userId}/water_logs/{logId}`
- **Fields:**
  - `amountMl` (number)
  - `date` (timestamp)
  - `createdAt` (timestamp)

### `journal_entries` (Subcollection)
Text entries.
- **Path:** `users/{userId}/journal_entries/{entryId}`
- **Fields:**
  - `title` (string)
  - `content` (string)
  - `mood` (string | null)
  - `date` (timestamp)
  - `createdAt` (timestamp)
  - `updatedAt` (timestamp)

### `progress_photos` (Subcollection)
References to Cloud Storage.
- **Path:** `users/{userId}/progress_photos/{photoId}`
- **Fields:**
  - `photoUrl` (string): Storage URL.
  - `date` (timestamp)
  - `weight` (number | null)
  - `notes` (string | null)
  - `createdAt` (timestamp)

### `achievements` (Subcollection)
Unlocked badges.
- **Path:** `users/{userId}/achievements/{achievementId}`
- **Fields:**
  - `type` (string)
  - `title` (string)
  - `description` (string)
  - `unlockedAt` (timestamp)
  - `metadata` (map)

### `streaks` (Subcollection)
Gamification records. Usually one doc.
- **Path:** `users/{userId}/streaks/{streakType}`
- **Fields:**
  - `type` (string): e.g., 'login', 'workout'
  - `currentStreak` (number)
  - `longestStreak` (number)
  - `lastActiveDate` (timestamp)
  - `updatedAt` (timestamp)

### `notifications` (Subcollection)
In-app alerts.
- **Path:** `users/{userId}/notifications/{notificationId}`
- **Fields:**
  - `title` (string)
  - `body` (string)
  - `type` (string)
  - `read` (boolean)
  - `link` (string | null)
  - `createdAt` (timestamp)

### `ai_conversations` (Subcollection)
- **Path:** `users/{userId}/ai_conversations/{conversationId}`
- **Fields:**
  - `title` (string | null)
  - `startedAt` (timestamp)
  - `lastMessageAt` (timestamp)
  - `summary` (string | null)
- **`messages` (Sub-Subcollection)**
  - **Path:** `users/{userId}/ai_conversations/{conversationId}/messages/{messageId}`
  - **Fields:**
    - `role` (string): 'user', 'assistant', 'system'
    - `content` (string)
    - `timestamp` (timestamp)

## 3. Recommended Indexes
Since data is strictly isolated per user, composite indexes are rarely needed unless sorting subcollections by multiple fields.
- `activities`: `date` (DESC)
- `daily_logs`: `date` (DESC)
- `journal_entries`: `date` (DESC)
- `messages`: `timestamp` (ASC)

## 4. Security Rule Recommendations
```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    // Lock down everything by default
    match /{document=**} {
      allow read, write: if false;
    }

    // User can access their own document and all subcollections
    match /users/{userId} {
      allow read, write: if request.auth != null && request.auth.uid == userId;
      
      match /{subcollection=**} {
        allow read, write: if request.auth != null && request.auth.uid == userId;
      }
    }
  }
}
```

## 5. Estimated Read/Write Patterns
- **High Read:** `users/{userId}`, `daily_logs`, `activities` (for rendering charts on dashboards).
- **High Write:** `water_logs`, `messages` (chat is write-heavy), `daily_logs` (saving mood multiple times).
- **Low Change:** `achievements`, `settings`.
